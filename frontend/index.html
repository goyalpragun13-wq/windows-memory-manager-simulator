📖 Windows Virtual Memory Manager (VMM) Architecture

1. Two-Tier Paging Subsystem

Unlike simplistic textbook page replacement algorithms that operate on a single monolithic global frame pool, the Windows NT/10/11 Virtual Memory Manager separates memory management into two distinct layers: Process Working Sets and the Global Page Frame Number (PFN) Database.

2. The PFN Database State Machine

Every physical frame in RAM is represented by an entry in the kernel PFN database and resides in one of the following states:

  • Active (Valid): Mapped in a process's hardware page table (PTE Valid bit = 1).
  • Standby List: Clean pages trimmed from working sets. Still hold process virtual data and pagefile mapping. Can be reclaimed via zero-disk-I/O Soft Faults.
  • Modified List: Dirty pages trimmed from working sets. Must be written to disk before reuse. Can also be soft-faulted prior to pagefile flush!
  • Free List: Physical frames with uninitialized contents available for new allocations.
  • Zeroed List: Frames pre-cleared by the idle-priority Zero-Page Thread for zero-fill demand paging (preventing inter-process data leakage).

3. Working Set Trimming & Soft Page Faults

When a process exceeds its Working Set quota or the system detects memory pressure, the Working Set Manager trims the least recently used pages. Clean pages move to the Standby list; dirty pages move to the Modified list. If the process touches that page again before it is overwritten, a Soft Fault occurs, re-linking the frame with zero disk access.

4. Replacement Algorithms & Belady's Anomaly

The experiment lab implements FIFO, LRU, Clock (Second Chance), and Optimal (MIN). Belady's Anomaly occurs when increasing physical frames causes an increase in page faults under FIFO, demonstrating why stack algorithms (like LRU) and working-set caching are preferred in production operating systems.
